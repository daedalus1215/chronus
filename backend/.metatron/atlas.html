05

How this was built

and what it cannot see

A script walks every .ts file under backend/src, extracts each import and export … from specifier, resolves it against the real file tree (src/-absolute and relative both), and classifies each file by its filename convention. Folder nodes are aggregated from those files; a folder's column is its most common file kind. External packages are dropped, so @nestjs/* and TypeORM do not appear.

Two honest limits. An import is not the same as an injection — the flow findings in section 03 were each opened and confirmed to be real constructor parameters, but the map at large counts imports, including type-only ones. And runtime wiring is invisible here: anything resolved through a NestJS DI token string rather than an imported symbol leaves no import edge, so the map understates dynamic coupling.
